# 早晨自动恢复失败：排查与修复目标

更新日期：2026-10-04。适用故障版本：`0.1.0-preview.1`，发布提交 `dd2dc1e`；修复开发基线 `20a3f27`。用户已确认修复版一晚自然跨夜验收成功；R1–R6 按本轮可用证据范围完成；新版最终包已安装到 E 盘，公开预发布及实际下载回读通过。

## 最终目标

夜间学校停网后，服务继续低频检测；学校恢复供网并允许有效账号认证时，在无人点击登录、无需重新输入密码、网卡和 IP 可以保持不变的情况下，自动完成必要的认证，并通过两项校园有线路径的公网探测。不得靠手动登录后的 Online、模拟结果或服务 Running 来判定这一目标通过。

保持三个开关独立、原有凭据保护、单次认证并发和目标门户限制。明确的账号密码错误、欠费、禁用仍应提示用户处理；暂时故障及无法确认原因的通用拒绝不应永久阻断恢复。安装包和程序位置另行核对，不直接移动已注册服务的文件夹。

## 已知事实与待查问题

- 用户确认 10-03 的 preview.1 早晨没有自动连接；该失败与 09-30 一晚成功保留历史。10-04 修复后台一晚验收通过。
- 10-03 保留日志从 09:53:42 开始，至 12:58:54 只有检测与旧拒绝原因，没有软件进入认证的记录；13:03:57 检测到公网可用，不证明软件自动登录。
- 源码在一次 `CredentialsRejected` 后持久化无限期拒绝保护；失败计数只选择检测间隔，没有认证次数上限。
- 通用 `ret_code=1` 被直接当成账号密码错误；现有记录没有保留分类码、首次拒绝时间、真实认证时间或操作来源。
- 首次触发事件已经轮转，对应原始响应未留存。欠费、夜间停网、账号错误、学校限流均不能据此确认为现场根因；禁止补造响应。

## 推进顺序与完成标准

### R1：离线复现并确认问题范围

状态：已完成离线复现。2026-10-03 新增 `RECOVERY-01`，旧实现检查退出码 1、0/1 通过；模糊拒绝后模拟等待到期，网卡不变时未再次提交，未恢复 Online。证据 `.local/recovery-repair-20261003/r1-before-fix.txt` 与 `r1-before-fix-result.json`。这证明阻断机制，不确认现场首次响应。

1. 使用假账号、进程内模拟门户和公网端点，复现“通用认证拒绝一次 → 后续学校允许登录 → 网卡不变 → 自动流程仍被阻断”。
2. 分别核对临时失败、明确账号错误、保护跨后台重启、手动重连、网页登录后的只读检测；确认哪些测试覆盖了旧行为，哪些恢复场景缺失。
3. 保存执行命令、退出码、假认证次数和状态，不访问真实校园认证端点、不读取用户凭据。

完成标准：可重复证明当前代码的阻断路径和恢复测试缺口；明确这一模拟场景只能证明软件机制，不能确认昨晚实际返回的响应。复现检查预期出现的失败单独记录，不包装成验收通过。

### R2：保留足以诊断下一次失败的脱敏证据

状态：源码与离线检查完成。首次拒绝摘要独立于事件轮转保存；记录实际发起请求的时间、操作来源和分类码，预检未提交不记为认证。五项针对性检查通过，旧文件兼容及假秘密扫描通过；过程中的两次测试失败和修正见验证记录。

1. 持久化首次保护时间与分类、最近真实认证时间与自动/主动来源、预计允许重试时间；区分实际提交被拒绝与保护期间跳过提交。
2. 减少重复“检测中/同一结果”覆盖事件，首次失败摘要独立于最近 80 条保留；兼容旧事件文件和旧配置。
3. 只保存固定原因码及固定中文消息。账号、密码、完整 URL、原始响应、MAC、个人内网地址和可复用会话不得进入日志或诊断导出。

完成标准：模拟跨重启和超过 80 条检测后仍能读回关键失败摘要；诊断能够区分自动认证、主动重连和只读联网发现；假秘密扫描通过，旧文件可读取。

### R3：修复拒绝分类、退避与旧保护兼容

状态：源码修复与离线检查完成。没有明确限制证据的通用拒绝按五分钟等待后继续自动尝试；明确密码、欠费、账号限制仍保护。旧模糊保护按五分钟兼容重验，重启不绕过等待；手动尝试的暂时失败也不清除已有明确保护。原三个开关与凭据密文保留。

1. 区分没有可靠账号错误证据的通用拒绝与明确账号限制；通用拒绝继续有限频率等待，不因一次响应永久停住。
2. 明确保护仍应保留，不因网卡事件、进程重启或一次普通检测绕过；手动重连仍只允许一次必要尝试。
3. 设计旧版本“已保护但无分类证据”的兼容流程，避免升级后仍无限卡住；不得静默更换用户账号、密码或开关。
4. 统一认证等待与周期退避，保证无忙循环、无并发提交、无次数用尽后的永久停止；暂停后不调度认证，部分公网可用时不重复登录。

完成标准：R1 的恢复场景在修复后无需人工操作自动完成，明确限制与保护测试仍通过；先更新 DEVELOPMENT 和对应 NET 验收，再改实现。恢复延迟只报告模拟结果，真实校园性能待实测。
