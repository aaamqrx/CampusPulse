# Campus-Flow 功能参考与 CampusPulse 取舍

核对日期：2026-09-26。

用户明确允许参考 [Campus-Flow](https://github.com/zuijiu888/Campus-Flow) 的功能。本文对照其 README 与可读取源码，把值得采用的行为转化为 CampusPulse 的需求；不直接复制其实现，不把源码静态检查当作运行验证。

参考来源：

- [项目说明 README](https://github.com/zuijiu888/Campus-Flow/blob/main/README.md)
- [主要源码 CampusAutoLogin.cs](https://github.com/zuijiu888/Campus-Flow/blob/main/work/CampusAutoLogin.cs)

下文的方法名称均指上述源码。GitHub 的 main 分支会变化，开发时应记录实际参考提交。整体设计以 [开发设计文档](DEVELOPMENT.md) 为准，验收以 [测试与发布计划](TESTING-AND-RELEASE.md) 为准。

## 1. 静默后台认证：采用

参考项目 README 描述后台认证时不打开浏览器或终端，源码 `BackgroundHost.Run` 实现后台运行流程。

CampusPulse 同样将日常认证放在后台。设置界面用于配置与诊断，网络恢复时不弹浏览器、不抢焦点。后台通过受支持的校园门户接口工作，不依赖模拟鼠标键盘。

关联：FR-03、NET-02、SYS-04。

## 2. 基础、高级、日志与关于页面：按首版范围采用

源码 `BuildTabs` 提供基础、高级、日志、关于四页。

CampusPulse 首版保留“连接与设置”“运行记录”“关于与帮助”的内容组织。首页显示联网状态及三个独立开关；帮助页写清支持范围、版本、许可证和反馈入口。

原项目的任意接口高级编辑能力不直接照搬到高权限后台。后续若加入学校模板编辑，应先定义目标地址校验、模板格式与版本兼容规则。

关联：FR-01、FR-04；后续学校模板扩展属于第二阶段。

## 3. 保存启用、测试登录、停止后台：采用并明确语义

源码 `BuildBasicPage` 包含保存启用、测试登录与停止后台操作。

CampusPulse 提供保存设置、立即检测、立即重连、暂停重连、启动/停止后台。

- 立即检测只读，不提交密码。
- 立即重连在确认必要时尝试一次认证，随后验证公网。
- 暂停重连保留后台、防睡眠和配置。
- 停止后台同时结束重连和防睡眠，不能隐藏这个影响。

关联：FR-02、FR-04、CFG-02、CFG-03、BOOT-05。

## 4. 开机自启动：采用，改为登录桌面前可运行

源码 `StartupManager` 使用当前用户的 `Run` 注册表项。这种实现依赖用户登录，不是系统服务启动机制。

CampusPulse 使用独立 Windows 服务；“开机自动运行”控制后台服务的自动延迟启动或手动启动。无需让 Windows 自动登录，也不要求开机弹出管理员设置窗口。

关闭自启后，当前后台继续运行；下一次开机不自动启动。手动打开设置窗口仍可启动后台，不能把服务设为无法手动运行的禁用状态。

关联：FR-02、BOOT-01 至 BOOT-05。

## 5. 请求字段、探测地址与间隔配置：采用可维护结构

源码 `BuildAdvancedPage` 可配置提交方式、字段、探测地址、成功内容和检查间隔。

CampusPulse 将这些能力组织成独立的校园适配模块和探测配置。首版内置当前已识别门户及电信规则，普通用户只填写账号密码；其他学校需要添加并验证适配器。

不向用户宣称“改一个网址就能支持所有学校”。校园门户配置发生变化时停止发送凭据，给出适配诊断。

关联：FR-05、NET-09；接口设计见 DEVELOPMENT.md 第 5 节。

## 6. 动态本机地址和表单识别：采用动态参数思想

源码 `Expand` 替换本机 IPv4 参数，`DetectForm` 尝试识别网页表单；README 也说明默认模板可使用当前内网地址。

CampusPulse 每次需要认证时重新获取与校园接口匹配的终端参数。当前校园页面实际采用 JSONP 接口，不能机械地套用普通 HTML 表单提交。

多网卡时依据通向校园门户的有线路径识别终端，公网探测也关联同一网络。无法确认路径时提示诊断，不能使用开发者的固定 IP 或把手机热点可用当作校园网恢复。

关联：NET-12、SYS-02、SYS-03。

## 7. 密码本机加密：采用，适配服务身份

源码 `SaveCredential` 使用 Windows DPAPI 的 `CurrentUser` 范围。

CampusPulse 的设置窗口与后台身份不同，因此由服务统一管理凭据。设计采用机器级 DPAPI，加上仅 SYSTEM 和管理员可访问的目录与文件权限；界面只获知是否已配置，不回读原密码。

机器级加密不能替代访问控制，权限验证是安装和升级的必测项。每位同学在自己的电脑上配置，分享安装包不包含开发者的账号。

关联：SEC-01 至 SEC-03。

## 8. 运行日志与问题定位：采用，限制数据范围

源码 `Log` 写本地日志，`BuildLogPage` 提供查看、刷新及打开目录功能；README 描述认证失败时记录 HTTP 状态。

CampusPulse 显示最近的状态变化和分类原因，支持复制脱敏事件。默认最多保留 80 条、最长 7 天。认证请求可能包含密码，所以原始 URL、原始请求/响应、Cookie 和明文密码均不进入日志或公开反馈。

打开日志目录不是首版必需操作；普通用户通过界面查看受限目录中的脱敏内容，避免为方便访问而放宽凭据目录权限。

关联：FR-04、SEC-02。

## 9. 网络事件、重复检测保护与低资源占用：采用并保留兜底检查

源码监听网络可用性和地址变化，`QueueCheck` 等逻辑限制重复工作；`SetConnected` 在判断联网后关闭定时器。

CampusPulse 保留事件唤醒、合并触发、单次认证和失败退避。联网后仍每 120 秒低频检查，以覆盖“网卡始终连接、IP 不变，但校园认证已失效”的情况。

这是针对本用户夜间断网场景的设计补充，不代表已在真实网络中复现原项目故障。README 的低 CPU 占用表述属于原项目主张，不能作为 CampusPulse 性能实测结果。

关联：NET-03、NET-05、NET-11；性能需要后续记录实际 CPU、内存和请求频率。

## 10. 清晰状态与明暗主题：采用状态呈现，主题后置

源码 `BuildHeader` 有状态标签、窗口控制和明暗切换；其中 `NightMode` 表示主题，不是夜间断网或定时登录策略。

CampusPulse 首版优先完成易读的中文状态、最近检测时间、失败原因和开关实际生效状态。明暗主题列为后续体验改进，不影响自动联网核心验收。

关联：FR-04；主题为后续可选功能。

## 11. CampusPulse 针对当前需求增加的内容

- **独立公网验证**：原项目的成功关键词可参与成功判定；本产品将门户接受认证与公网可用分开记录，HTTP 200 或关键词不单独构成验收通过。
- **正式安装与升级卸载**：提供自包含安装包、后台注册、配置迁移和凭据清理。
- **可选插电防睡眠**：关闭窗口后仍由后台管理，停止后台或转电池时释放。
- **公开构建与发布记录**：源码、测试与构建流程进入公开 GitHub，安装包放 Releases，未验证项明确列出。
- **托盘入口**：属于 CampusPulse 的设计需求。本次可见 README 和源码范围不足以确认 Campus-Flow 是否已有完整托盘功能，因此不把它列为原项目已证实功能。

本次没有发现足以确认原项目具有“按夜间时间表上下线”的证据。CampusPulse 也不需要准确的早晨恢复时间，依赖持续的低频检测与网络事件恢复。

## 12. 参考结论的使用规则

本文件只决定功能参考与产品取舍，不证明 Campus-Flow 在本校可用。继续开发时以当前学校页面和测试证据核对协议，以本项目需求决定行为，不为复刻参考项目而引入不需要的功能。

参考仓库若后续变化，更新本文件的核对日期与结论；需要引入实际第三方代码时，单独核查许可证和来源，不能把“允许参考功能”理解为所有源代码均可无条件复制。
