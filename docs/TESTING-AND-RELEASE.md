# CampusPulse 测试、验收与发布计划

本文规定开发完成后必须执行的检查，不表示这些检查已经通过。适用版本为 `0.1.0-preview.1`。

## 1. 验收目标与支持范围

- 目标：校园网恢复供网且允许认证后，电脑自动登录并恢复通过校园有线网访问互联网。
- 首版环境：Windows 11 x64，持续插电、保持开盖的笔记本，有线校园网。
- 默认门户：`http://10.62.164.38/`，Dr.COM，无验证码；旧地址 `10.62.164.14` 于 2026-09-29 返回跳转页。用户可填私有 IPv4 的 HTTP 门户首页，认证仍须通过相同 Dr.COM 页面及配置核对。
- 已知停网时间为每天 23:30，恢复时间未知，程序不得要求用户配置准确来网时间。
- 页面列出的四项：中国联通、中国移动、中国电信、校内网（无外网）。校内网选项不计为公网恢复。其他认证协议、域名或 HTTPS 门户及无线网络须另行适配和验证；四项真实登录仍待实测。
- 用户已明确排除 UU 远程测试；UU 启动、连接及远控成功均不作为本项目验收项。
- 自动认证只使用用户自己的有效账号，不绕过停网政策、不绕过认证或账号限制。

后续顺序按用户最新决定调整：开发阶段使用 `scripts/check-dev.ps1` 直接构建和验证功能；所有适用功能修改并完成验证后，才重新生成 EXE 安装包。历史预览包不作为当前验收入口。

2026-09-30 本轮新增源码检查为四项目 Release 0 警告/错误、29/29 离线通过；本机开关/后台重启、电源请求、拔电切换、锁屏及权限的逐项证据见 [本机验收记录](LOCAL-ACCEPTANCE.md)。21:06 新修复已部署并完成一次异常结束/恢复检查；不是全矩阵通过，剩余现场项及安装生命周期仍须分别完成。

每次验收记录版本号、提交标识、Windows 版本、测试场景、预期结果、实际结果、时间及证据位置。结果只能填写“通过”“失败”“未执行”或“不适用并说明原因”。

证据分为以下等级，各等级分别记录，不得相互替代：

1. **源码与文档检查**：文件存在，需求可追踪，代码审查完成；不代表可以编译运行。
2. **可重复构建与自动化测试**：指定提交在干净环境构建成功，测试输出可追溯；不代表安装成功或适配真实学校。
3. **本机安装及运行**：安装、服务、界面、权限、升级、卸载在 Windows 上验证；不代表校园认证成功。
4. **真实认证及恢复**：用户在本机填写凭据，完成真实登录和可控断线恢复；不代表跨夜运行可靠。
5. **跨夜运行**：本次首个预览版按用户 2026-09-30 的决定接受 1 个实际断网与自动恢复的夜晚。当前证据为用户现场确认；若没有后台脱敏事件时间线或当日独立有线公网复查，应明确写出，不能声称已取得这些证据或证明多夜稳定性。

公开说明按已经取得的证据陈述。一次跨夜成功仍持续标注为预览版，说明实测夜数和证据边界，不使用“已保证自动恢复”等措辞。

## 3. 测试准备

1. 在独立 Windows 测试环境完成模拟网络和安装测试；记录服务原始启动类型、电源设置及已有配置。
2. 使用本地模拟门户及探测端点覆盖错误响应，默认禁止自动化测试访问真实校园门户。
3. 测试账号只使用专门的假数据；真实校园密码由用户在本机界面输入，不放入聊天、仓库、CI 变量或测试报告。
4. 进行会中断联网的实测前，安排现场操作条件；不得为了验证而在无人值守时远程停用唯一网卡。
5. 保存失败场景的脱敏日志；原始抓包、凭据文件、本机配置和完整认证请求地址只留本机受限目录。
6. 公开 GitHub CI 无法访问校园私网，必须以模拟测试为主；真实校园测试记录与 CI 结果分开。
7. 开发阶段可用 `scripts/dev-service-validation.ps1` 临时注册固定的 `CampusPulse` 服务并打开正式界面。管理员执行前确认本机无同名服务及数据目录；先用无凭据配置核对服务、开机启动、防睡眠和界面状态，结束后运行 `Remove` 并复核。该流程不运行产品安装包，不能替代安装、升级、卸载验收。自动重连开启后的行为须在隔离模拟环境或用户本机真实凭据场景单独验证，假密码不得发往真实校园门户。

## 4. 功能验收矩阵

以下编号用于关联测试代码、人工记录及发布检查。部分编号已有离线模拟证据，完整的系统与真实网络验收仍须逐项执行；不能因共享编号而将整项标为通过。

### 配置与控制

1. **CFG-01 初次启动与无凭据**：全新安装后查看开关并启动服务。应为 `Enabled=false`、`StartWithWindows=true`、`UnattendedMode=false`；无账号密码时零认证请求，并明确提示需要配置。
2. **CFG-02 保存及测试登录**：在本机填写门户首页、账号、密码并选择运营商，保存后重开界面。应显示已配置且不回填明文密码；“立即检测”零认证请求，“立即重连”检测后最多提交一次必要的受控认证，并显示可理解的结果。
3. **CFG-03 自动重连开关**：启用后模拟断网，应进入检测与恢复流程；暂停后不得调度新的自动认证。若已有请求无法取消，应等待其超时或结束并如实显示状态，不能形成新重试。
4. **CFG-04 配置一致性**：关闭界面、重启服务再读设置。三个开关、运营商及门户地址应保持一致；更换账号、运营商或门户地址必须重新输入密码。旧配置升级后应暂停自动重连，不复用旧后缀对应的密码；写入失败不得显示“保存成功”。使用假凭据和被占用的配置文件验证保存失败后旧配置、旧凭据均保留，临时文件清理完成。
5. **CFG-05 独立开关**：启用无人值守后暂停自动重连。防睡眠请求应继续存在；反向操作同样验证。界面清楚说明两个功能独立。
6. **CFG-06 输入校验**：空账号、空密码、后缀与选项不匹配、重复后缀，以及本机、公网、链路本地、域名、HTTPS、带路径或账号参数的门户地址分别测试。应在发送前给出原因，正确处理编码，不泄漏原始密码或整条请求。

### 认证、探测与重试

7. **NET-01 已经联网**：模拟合法公网探测结果。应保持在线并低频检查，不重复提交校园登录。
8. **NET-02 需要认证**：模拟符合适配特征的门户及未认证状态。应提交正确运营商参数，随后独立验证公网可用性；仅有登录成功响应不能判定联网成功。
9. **NET-03 断网但网卡不变**：保持以太网连接及原 IP 不变，使认证失效。应由周期检查发现并恢复，不能只依赖网卡连接事件。
10. **NET-04 23:30 停网与未知恢复时间**：模拟长时间网关或认证服务不可达，再于任意时间恢复。应持续低频等待，恢复后继续认证，无固定早晨时间依赖。
11. **NET-05 暂时故障退避**：依次返回超时、连接失败、临时服务错误及带 `Retry-After` 的 HTTP 429。应按设计中的有上限退避及抖动重试，尊重服务端可信等待提示且最长不超过 300 秒，不产生高频请求；模拟多次网络变化通知，普通事件不得取消在途检查或提前绕过已排定的下次检查，人工操作仍可即时执行。
12. **NET-06 明确凭据错误**：返回经适配确认的密码错误或账号无效响应。应停止自动重复提交并要求用户处理；更新凭据或明确手动重试后才能再次尝试。
13. **NET-07 其他错误分类**：分别模拟欠费、策略限制、会话冲突、未知响应。应保留准确分类或显示“未知认证错误”，不得统称密码错误，也不得自动执行强制下线操作。
14. **NET-08 HTTP 200 假成功**：探测返回状态码 200，但内容为登录页、广告页或错误正文。应判定验证不通过；测试应断言期望内容而非只检查状态码。
15. **NET-09 重定向与门户变化**：返回重定向、异常脚本、不匹配的认证页面，以及 gzip 压缩或超大解压后的脚本。旧首页跳转时应在发送密码前停止，不能自动把凭据转发给新主机；用户明确选择并保存新首页后仍须核对配置、模板及脚本版本。有效 gzip 脚本应解码；未知压缩格式或超限内容应阻断认证。
16. **NET-10 DNS 与探测服务故障**：让 DNS 失败或单个公网端点不可用，并模拟 VPN/TUN 把系统 DNS 结果替换为 `198.18.0.0/15` 假地址。固定探测域名应优先通过所选有线接口的 DNS 解析，拒绝假地址；单个公网来源验证成功时报告检测受限或已联网的相应证据，不因另一个端点故障持续重复登录。仅在门户明确需要认证且其他条件满足时才允许认证。
17. **NET-11 超时及并发**：同时触发网络变化、周期检测、手动检查。认证并发数始终不超过 1；所有请求有超时，停止服务后不再产生请求。
18. **NET-12 账号与运营商编码**：按实际 `pc.js` 模板的 `@unicom`、`@cmcc`、`@telecom`、空值逐项使用假账号密码验证；旧 `@dx`/`@lt`、重复或错配后缀应拒绝。只有 `ISP_select` 中唯一的所选后缀可以授权提交凭据；模板缺少所选项、其他下拉框出现同名项或重复后缀时不得提交密码。校内网在线不能报告公网恢复。

### 代理、多网卡与系统生命周期

19. **SYS-01 系统代理**：在设置代理和代理不可用两种情况下检查校园认证。认证及联网探测应按明确的直连策略执行，不把凭据交给系统代理。
20. **SYS-02 多网卡**：同时启用有线校园网和另一条可上网连接，并加入 VPN/TUN 虚拟网卡，即使全局最优路由指向虚拟网卡，也应使用指定物理以太网接口与源地址核对到门户的路由，并把 DNS 与两个公网探测绑定到该接口。多条有效物理路径应保守拒绝；备用网络在线不能使界面错误报告校园有线网已恢复。保存用户配置后，在正式后台重复只读检测并核对实际界面状态。
21. **SYS-03 拔线与地址变化**：拔插网线、续租地址或改变默认路由。应等待有效链路和地址，再恢复探测；旧请求不得把过时结果覆盖新网络状态。
22. **SYS-04 息屏与锁屏**：保持服务运行，关闭窗口并锁定 Windows。后台继续工作，息屏不被防睡眠模式禁止，托盘进程退出不影响服务。
23. **SYS-05 睡眠或休眠恢复**：关闭无人值守模式并在系统支持时手动睡眠、休眠，再唤醒。服务应等待网络就绪后重新检查，清理过时超时和重试状态，不集中补发请求。
24. **SYS-06 服务故障恢复**：使服务异常退出。应按已配置的有限恢复策略重新启动，配置可读且不形成崩溃循环；回读恢复动作必须为 5/15/60 秒重启后 NONE，86400 秒无故障后重置计数，不能以重复重启作为末项。界面能区分服务离线和网络离线。

### 开机自启动

25. **BOOT-01 默认开启**：首次安装后检查服务启动类型并重启电脑，在尚未登录 Windows 时验证服务已启动。未开启自动重连或未配置凭据时仍不得提交认证。
26. **BOOT-02 关闭自启**：在界面关闭 `StartWithWindows`，立即检查持久化值及服务启动配置，重开界面确认一致。当前服务保持运行；下次重启后不自动运行，不额外自动启动托盘。
27. **BOOT-03 重新开启**：再次启用自启，确认保存成功并重启。后台恢复自动启动；是否自动认证仍由 `Enabled` 和凭据状态决定。
28. **BOOT-04 权限或写入失败**：模拟取消提权或无法修改服务配置。界面应明确失败，回读实际状态，不把仅保存的期望值冒充系统已应用值。
29. **BOOT-05 关闭自启后手动使用**：重启后由用户手动打开程序并请求启动后台。按权限要求启动服务后可正常使用；仅打开窗口不擅自把自启重新打开。

### 无人值守与凭据保护

30. **PWR-01 插电值守**：接通电源并开启 `UnattendedMode`，等待超过原空闲睡眠时间。应阻止空闲睡眠且允许息屏；测试前后系统电源计划不被永久修改。
31. **PWR-02 释放请求**：关闭无人值守、停止服务、正常退出服务及模拟服务崩溃。防睡眠请求均应释放，不留下持续改变系统行为的设置。
32. **PWR-03 电源切换**：开启无人值守时拔掉电源，再接回。电池供电时应释放防睡眠请求，恢复插电后重新申请；不得声称能阻止用户主动关机或系统强制休眠。
33. **SEC-01 文件及通道权限**：以普通无关本地用户访问服务凭据文件和控制通道。应拒绝敏感读取及未授权控制；已授权界面只获得凭据是否存在，不读取已存密码。
34. **SEC-02 明文泄漏检查**：使用醒目的假密码进行保存、认证失败及诊断导出，搜索日志、配置、异常和导出文件。应无明文密码、含密码请求 URL 或可复用认证材料。
35. **SEC-03 凭据更换与清除**：更新密码后验证旧数据不可再被服务使用；更换账号但未输入新密码时拒绝保存，避免沿用旧账号的密码；清除凭据后停止后续认证并提示重新配置。

补充检查：认证拒绝保护必须跨服务重启保留；事件记录最多 80 条且最长 7 天；对正在认证时的网卡变化、暂停及配置切换使用操作版本或取消机制，旧结果不能覆盖新状态。

## 5. 安装、升级与卸载验收

1. **打包前检查**：构建目标为 Windows x64，自包含发布。清单中包含 WPF 程序、服务及依赖；不得包含用户配置、真实凭据、开发缓存、日志或私钥。
2. **干净机器安装**：在未预装 .NET 的 Windows 11 x64 上安装，检查所需管理员授权、安装路径、快捷方式和服务注册。取消安装或取消提权时应退出并清理本次未完成的注册。
3. **安装后默认行为**：服务可随开机运行，但自动重连默认关闭，无人值守默认关闭；无凭据时零认证请求。界面明确说明开机启动针对后台服务。
4. **重复安装与路径**：对同版本重复安装及包含空格、中文的允许路径测试，不产生重复服务、重复启动项或损坏配置。
5. **升级保留**：从前一预览版升级，验证配置、凭据及三个开关原样保留，服务停止和文件替换有序，配置迁移失败时保留可恢复的旧数据并报告失败。
6. **升级失败**：模拟文件占用、磁盘空间不足和服务停止失败，不继续宣称安装成功；确保能按文档恢复或重新安装，不遗留两个并行服务。
7. **版本降级**：不支持的降级必须提前提示或拒绝，不能用旧程序静默覆盖新格式配置。
8. **卸载**：确认服务及其进程停止、防睡眠请求释放，移除服务、自启配置、程序文件、快捷方式及凭据，按卸载约定清理本机配置和日志。不得卸载其他软件或改变系统电源计划。
9. **卸载后复核**：重启后无 CampusPulse 后台及认证请求；重新安装表现为首次安装，不读到旧凭据。
10. **安装包身份**：记录文件名、版本、SHA-256、签名状态及验证方式。未签名的预览包明确标记“未签名”，不能描述为已经完成代码签名。
11. **Windows 提示**：记录 SmartScreen 或安全软件的实际表现。说明来源和校验方式，不要求用户关闭防病毒、防火墙或系统安全功能。

## 7. GitHub 公开仓库与发布流程

拟公开仓库为 `aaamqrx/CampusPulse`。创建及首次上传后必须实际回读仓库名称、可见性、默认分支和文件清单；在此之前不得称其已创建。

1. **提交前整理**：确认独立实现的 MIT 许可、README、支持范围、安装方法、开发文档和反馈模板。若引入第三方代码或资源，先核对其许可并保留要求的声明。
2. **提交扫描**：除 `.gitignore` 外，检查全部待提交内容和已有 Git 历史。搜索真实账号、密码、令牌、认证请求、原始抓包、凭据库、私钥和本机日志；误提交的敏感数据必须先处理历史并在需要时撤销相关凭据。
3. **配置样例**：只提交明确的假数据和无密钥模板；学校门户地址属于适配信息，真实账号及可复用认证材料不属于公开配置。
4. **公开创建与上传**：按用户已授权的公开开源范围创建仓库并推送源码，验证远端可读。不能因为本机目录存在就报告 GitHub 上传完成。
5. **普通提交 CI**：执行还原、构建、自动化测试和静态检查，保留不含秘密的报告；失败必须阻止后续打包发布步骤，不跳过测试以获得绿色结果。
6. **发布标签**：使用 `v0.1.0-preview.1` 等明确预览标签。标签构建也必须从该标签重新运行检查，生成自包含程序、安装包及 SHA-256。
7. **自动发布边界**：标签流程最多创建 GitHub 草稿 Release，并标为 prerelease；构建产物先附于草稿供检查，不自动公开为正式版，不设为稳定版最新版。
8. **检查失败处理**：任何构建、测试、打包或校验失败均保持草稿未公开；记录失败并修复，不上传旧包冒充新标签的产物。
9. **公开预览发布**：功能验收后重新打包，人工核对安装包与标签一致、基础安装测试通过、无凭据泄漏后公开 prerelease。已执行与未完成的真实认证及跨夜结果逐项写明，不用旧包替代新构建。
10. **稳定版门槛**：功能、安装生命周期、真实认证和跨夜必测项全部通过，无未解决的凭据或失控重试问题，才评估稳定版；签名状态无论如何都如实披露。
11. **反馈处理**：问题模板只索取软件版本、Windows 版本、场景和脱敏诊断；提醒勿贴账号密码、完整抓包或带秘密的请求地址。

每份 Release 说明至少包含支持范围、变化、安装包校验值、签名状态、已执行检查、未验证项和已知问题。

## 8. 开发里程碑与交付门槛

1. **M0 文档定稿**：需求、架构、配置默认值、支持边界、验收与发布计划一致。该阶段已完成；后续只凭对应运行证据认定功能完成。
2. **M1 认证与状态机**：完成门户适配、直连探测、并发控制、错误分类及退避；使用模拟端点完成 NET 和相关 SEC 测试。
3. **M2 Windows 后台**：完成受限控制通道、凭据保护、自启动配置和防睡眠生命周期；通过 CFG、SYS、BOOT、PWR 的适用测试。
4. **M3 设置界面**：完成账号配置、三个开关、手动检查、状态及脱敏诊断；界面读到的状态与服务实际行为一致。
5. **M4 开发运行与校园验收**：不依赖安装包验证本机界面、后台与系统行为；用户本机真实手动登录已有系统证据，1 晚自然跨夜自动恢复按用户现场确认接受。受控认证失效、后台跨夜事件回读及多夜稳定性未验证，不能据此标为通过。需要服务注册的系统项可用受控临时注册验证，结果单独标明；完成适用的本机系统和界面验收后才进入 M5。
6. **M5 最终安装包**：功能修改与适用验收完成后重新构建自包含 EXE，实际验证安装、升级、卸载和干净 Windows 环境，记录校验值与签名状态。

每个里程碑只在对应证据齐备后标记完成。构建成功、安装成功、网络恢复、公开上传是四个独立结果，应分别汇报。
